# Internationalisation

TLDR: the app UI speaks English, Burmese, Bahasa Indonesia, Tagalog and Thai. English is the source and the fallback. The other four are machine translated with Gemini and wait for native review. Run `pnpm i18n:check` to see what is missing or unreviewed.

## How it works

- Library: i18next with react-i18next and expo-localization. It has typed keys, interpolation and CLDR plurals, and it switches language at runtime without a restart.
- Files: `src/i18n/locales/<lang>/<namespace>.json`. English is the source. The English files define the key types, so a missing or misspelled key is a compile error (`pnpm typecheck`).
- Namespaces: `common`, `onboarding`, `home`, `check`, `checking`, `contacts`, `help`, `radar`, `account`, `settings`, `shield`, `errors`, `report`, `feedback`, `learn`.
- Use `const { t } = useTranslation('home')` in components. Use `useTranslation(['home', 'common'])` and `t('common:actions.back')` for keys from another namespace. Code outside React imports `t` from `src/i18n`.
- Text and buttons: import `Text` and `TextInput` from `src/components/Text`, not from `react-native`. They pick A10 YoeShin (Burmese) or Noto Sans Thai by script and widen the line height (`src/theme/script.ts`, `src/theme/localizedText.ts`). `Button`, `Chip`, `Pill` and `LinkButton` in `src/components/ui.tsx` already use them.

## Burmese font

- Burmese uses A10 YoeShin Regular and Bold (`assets/fonts/A10_YoeShin-*.ttf`, registered as `A10YoeShin-Regular` and `A10YoeShin-Bold`). Semi-bold and heavier text maps to Bold.
- The font has its own Latin glyphs, but the web style still lists Plus Jakarta Sans after it, so "SafeRoute" and other Latin words in Burmese strings keep the app face.
- Line height for Burmese is the Latin line height times 1.2 (`src/theme/script.ts`). YoeShin has a content height of 1.42 em.
- Licence: the user supplied the font. Its name table reads "(c) 2025 The Akkhayar. All Rights Reserved." and names no licence. The licence is unconfirmed.

## Language rules

| Setting | Behaviour |
| --- | --- |
| UI language | English, Burmese, Bahasa Indonesia, Tagalog, Thai. Saved on the device under `saferoute.uiLanguage.v1`. |
| No saved choice, Android | Device locale if supported, else English. |
| No saved choice, web | Always English, whatever the browser locale. Judges see English unless they pick another language. |
| Onboarding | The language chip sets the UI language at once and the check language. |
| Settings | "App language" sets both. "Report language" sets only the check language. |
| Check language | `en`, `id`, `tl`, `my` only. |

Thai: `docs/api-contract.md` lists `language` as `en | id | tl | my`, and the server rejects other values (`LANGS` in `server/src/types.ts`, a zod enum). The app never sends `th`. A Thai UI sends `en`, so Thai users read the verdict in English. The Thai UI shows a note about this. Adding `th` to the backend needs a server change, the prompts and the TTS voice. Then change `checkLanguage` for `th` in `src/i18n/languages.ts`.

## Add or change a string

1. Add the key to the English file, for example `src/i18n/locales/en/home.json`.
2. Use it: `t('check.title')`. TypeScript checks the key.
3. Run `pnpm i18n:translate`. It translates only the missing keys in the other four languages.
4. Run `pnpm i18n:check` and commit the JSON files.

Plurals use i18next suffixes and a `count` option: `"reports_one"` and `"reports_other"`, then `t('reports', { count: 3 })`. Write `_one` and `_other` in English. The script makes the forms each language needs: Tagalog has `_one` and `_other`. Burmese, Indonesian and Thai have `_other` only.

Interpolation uses `{{name}}`. Never translate the name inside the braces.

Copy rule: say "looks risky", "shows warning signs" or "likely". Do not say "this is a scam", "fake", "confirmed" or "scammer". The translation prompt repeats this rule.

## The translate script

`scripts/translate.mjs` reads `GEMINI_API_KEY` from the environment or from `~/work/scamshield-secrets/.env` (set `SAFEROUTE_ENV_FILE` to use another file). It never prints or stores the key.

- `node scripts/translate.mjs --lang my --ns home` limits the run. `--dry-run` lists what would change.
- The model is `gemini-3.8-flash`. Set `GEMINI_TRANSLATE_MODEL` to change it.
- The glossary is in the script. SafeRoute, Screen shield and Message Guard stay in English. The verdict names (Low risk, Be careful, High risk; the safe verdict stays "Low risk", not "Safe"), Scam radar and Trusted contacts have fixed translations per language. Native reviewers may change them. Edit the glossary and the JSON together.
- Tone: plain, short and kind, for readers with low literacy. Burmese is standard Unicode, never Zawgyi.
- Every new file starts with `"_meta": { "reviewed": false }`. The script also removes keys that no longer exist in English.

## Review translations (native speakers)

1. Run `pnpm i18n:check --keys` to list unreviewed keys, or open the files under `src/i18n/locales/<lang>/`.
2. Read each value next to the English file. Fix meaning, tone and length. Short labels must stay short: they sit in buttons and chips. Keep `{{placeholders}}` as they are.
3. Check the glossary terms are used the same way everywhere.
4. When a whole file is correct, set `"_meta": { "reviewed": true }` in that file.
5. If you review part of a file, keep `reviewed: false`. When a file is `reviewed: true`, new keys are added to `_meta.unreviewed` and need a second pass. Remove the key from that list when it is checked, and remove the list when it is empty.
6. Open a PR with the JSON changes only.

`pnpm i18n:check` exits with an error when keys are missing. It reports unreviewed keys but does not fail on them. `pnpm i18n:check --strict` also fails on unreviewed keys.

## Add a language

1. Create `src/i18n/locales/<code>/` and an `index.ts` like the one in `src/i18n/locales/id/`.
2. Add the language to `resources` in `src/i18n/resources.ts`, to `UiLanguage` and `UI_LANGUAGES` in `src/i18n/languages.ts` (set its `checkLanguage`), and to `TARGETS` in `scripts/translate.mjs` and `scripts/i18n-check.mjs`.
3. If the script is not Latin, Myanmar or Thai, add its font to `src/theme/script.ts`, `src/theme/theme.ts` and `src/App.tsx`.
4. Run `pnpm i18n:translate` and `pnpm i18n:check`.

## Not translated yet

- Native overlay pill, result card and notification strings in `modules/shield-module` (Kotlin). Follow-up: move them to Android resource files (`values-my`, `values-in`, `values-fil`, `values-th`) and pass the UI language to the module.
- The example screens under `src/screens/demo/**` copy the native overlay and stay English until that follow-up is done. The Learn guide says so under the example.
- `ShieldScreen` is converted on the local branch `feat/i18n-shield` and waits for the Message Guard merge. Its strings in `en/shield.json` (`needs.*`, `checkNow`, `checking`) arrive with that commit.
- Learn text lives in `src/i18n/locales/<lang>/learn.json`. `src/screens/learn/content.ts` holds structure only (ids, icons, flag families, demo keys) and reads text through getters, so it follows the active language.
- Server-side copy: hotline names and notes (`src/data/hotlines.ts`, official language), the mock API copy (`src/api/mockCopy.ts`), the model verdicts (already follow the check language) and the `/privacy` and `/delete-account` pages stay English.
- History entries keep the label they were saved with (for example "Screenshot, Bangkok").

## Fonts and clipping

Burmese needs about 1.35 times the line height of Latin text. Thai needs about 1.15 times. The `Text` wrapper applies this. Containers use `minHeight`, not a fixed `height`, so Burmese can grow them. Check new layouts with `pnpm build:web` and a Burmese screenshot.
